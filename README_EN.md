# 🔬 PlateArrangers

*Automated image renaming and reorganization tool for 96-well microscopy plates.*

*Available in: [English](README_EN.md) | [Français](README.md)*

Contact: @gmaubon / maubon.com

---

## 📋 Overview

During High-Content Screening (HCS) campaigns or automated acquisitions on 96-well microplates, imaging instruments often export TIFF images with raw sequential names that do not reflect experimental coordinates.

**PlateArrangers** organizes and renames these image series by applying a standardized and rigorous naming convention, mapping each image to its well coordinate, field of view (site), and wavelength (channel), according to the acquisition sequence detailed below.

*Originally, this software was designed for images acquired on a **Revolution** microscope from **Discover Echo Inc.** to facilitate downstream automated processing in **CellProfiler**.*

---

## ✨ Key Features

- **Modern Graphical Interface**: Built with [CustomTkinter](https://github.com/TomSchimansky/CustomTkinter), featuring real-time switching between *Dark*, *Light*, and *System* themes.
- **Internationalization & Custom Languages (i18n)**: All interface strings are decoupled into plain text (`.txt`) translation files. The application automatically discovers new language files in the `languages/` folder and allows instantaneous language switching without restarting.
- **Dynamic File Detection**: Real-time inspection of the source folder with a visual color indicator (green/red badge) showing the number of TIFF images (`.tif`, `.tiff`, `.TIF`, `.TIFF`) found.
- **Partial Plate Support**: Configurable starting well (e.g., `A01`, `C04`), allowing users to process plates where imaging did not begin at the first well.
- **Multichannel & Multisite Management**: Fully adjustable parameters for the number of fields of view (sites) per well and number of acquisition wavelengths (channels).
- **Non-Destructive Processing**: Source files are never modified or moved; they are copied with full metadata preservation (`shutil.copy2`).
- **Safe Automatic Stop**: The process terminates cleanly as soon as all available physical source files have been assigned, preventing index out-of-range errors.
- **Traceability Report**: Automatically generates a `rapport_renommage.txt` file in the destination folder, recording execution parameters and an exact map of old filenames to new filenames.
- **File Explorer Shortcut**: End-of-processing dialog allows opening the destination directory directly in Windows Explorer.

## 📥 Input File Format & Acquisition Sequence

### Raw File Format
Files generated by the imaging instrument are named sequentially:
```text
Tile000001.tif
Tile000002.tif
Tile000003.tif
...
```
*(Supported extensions: `.tif`, `.tiff`, `.TIF`, `.TIFF`)*

### 96-Well Plate Mapping
Each raw image corresponds to:
- A **Well (`P`)** on the 96-well microplate, identified by a **Row (`L`)** from `A` to `H` and a **Column (`C`)** from `1` to `12` (e.g., `A01`, `B03`, `H12`).
- A **Wavelength (`W`)** (acquisition channel), ranging from `W1` to `W[nb_wavelengths]`.
- A **Field of View (`S`)** (*Site / Field*) within that well, ranging from `S1` to `S[nb_fields]`.

### Acquisition Order Sequence
The instrument outputs images in a continuous linear progression:
1. **Starting Point**: Starts at the first field (`S1`) of the starting well (by default row `A`, column `1`, i.e., `A01`) in the first wavelength (`W1`).
2. **Field Progression**: Acquires the next field (`S2`), then `S3`, up to the last configured field for that well.
3. **Wavelength Progression**: Once all fields for that well and wavelength are imaged, moves to the second wavelength (`W2`) and repeats through fields (`S1`, `S2`...).
4. **Next Well Progression**: Once all wavelengths and fields for this well are complete, advances to the next well on the same row (column `2`, e.g., `A02`), and so on.
5. **Next Row Progression**: Upon reaching the last well in column `12` of row `A` (`A12`), moves to the first well of the next row (column `1` of row `B`, i.e., `B01`).
6. **End of Plate**: This progression continues until the last well of the plate (`H12`) is completed or until all available source images have been processed.

## 🏷️ Output File Naming Convention

Each output file follows this standardized format:

```text
[ProjectName]-[Well]-[Column]-[Row]-S[Field]-W[Wavelength].[EXT]
```

### Example:
For a project named `Experience_01`, the 2nd field of view and 1st wavelength of well **B03** will be named:
```text
Experience_01-B03-03-B-S2-W1.TIFF
```

### Component Breakdown:
- **`[ProjectName]`**: Name of the experiment or assay (e.g., `Exp01`, `Screening_HeLa`).
- **`[Well]`**: Standardized 96-well coordinate (from `A01` to `H12`).
- **`[Column]`**: 2-digit column index (from `01` to `12`).
- **`[Row]`**: Row letter (from `A` to `H`).
- **`S[Field]`**: Field index (*Site / Field*), from `S1` to `S[nb_fields]`.
- **`W[Wavelength]`**: Channel index (*Wavelength*), from `W1` to `W[nb_wavelengths]`.
- **`.[EXT]`**: Preserved original extension capitalized (e.g., `.TIFF`).

## 🚀 Installation & Usage

### Prerequisites
- **Python 3.8+**
- Required library:
  ```bash
  pip install customtkinter
  ```

### Launching the Application
Run the main script:
```bash
python app.py
```

### Step-by-Step Instructions
1. **Source Folder**: Click *Browse...* to select the directory containing your raw TIFF files. The counter badge instantly displays the number of detected files.
2. **Destination Folder**: Select the destination directory where renamed images will be copied.
3. **Parameters**:
   - Enter your **Project Name**.
   - Enter the **Starting Well** (e.g., `A01`).
   - Specify the **Number of Fields** per well.
   - Specify the **Number of Wavelengths**.
4. **Execute**: Click **🚀 Start Processing**.
5. Once complete, a success dialog appears with a shortcut button to open the destination folder directly, view the renamed images, and inspect `rapport_renommage.txt`.

## 🌐 Internationalization & Adding a New Language

PlateArrangers allows anyone to create and add new languages easily without writing any code:

1. Open the `languages/` folder (located in the project root or next to `PlateArrangers.exe`).
2. Duplicate `en.txt` (or `fr.txt`) and rename it (e.g., `es.txt`, `de.txt`, `it.txt`).
3. Open the new file in **Notepad** (or any text editor).
4. Update the language display name:
   ```text
   LANG_NAME = Español
   ```
5. Translate the values after the `=` sign for each variable.
6. Save the file with **UTF-8** encoding.
7. Launch PlateArrangers (or select the dropdown menu): your new language will appear in the selector at the top right!

> **Fallback Safety**: If any key is missing from a translation file, PlateArrangers automatically falls back to default French text, preventing crashes or blank labels.

## 📦 Building a Standalone Windows Executable (.exe)

The application can be compiled into a standalone Windows executable requiring no Python installation on the target machine:

```bash
pip install pyinstaller
pyinstaller PlateArrangers.spec
```

The resulting executable will be available in `dist/PlateArrangers.exe`.
